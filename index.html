PanSense

Sees what's in the pan, how cooked it is, and what to do next, from one overhead camera.

My first doneness model barely beat a constant guess: the features recognised which video it was, not how cooked the food was.

Measuring each frame as change since the food went in fixed it on all 30 of 30 held-out videos.

A computer-vision pipeline for a cooking robot, built only from public data. Grounding DINO and SAM turn ingredient tags into pixel masks, which train a small segmenter fast enough for the robot. Frozen DINOv2 features of the food track doneness, a clock-aware model decides when it's done, and a rule layer explains each action: wait, stir, add, check heat or stop.

Python, PyTorch, DINOv2, Grounding DINO, SAM, YOLO, ONNX Runtime, scikit-learn. 95% bootstrap intervals and paired tests on every result.

In progress: the dataset is growing from 30 to about 80 clips, and the numbers above will move.

GameSmith

An agent platform that writes puzzle games, proves they're solvable, repairs its own mistakes and learns from them.

Learned rules lifted first-try success from 62% to 88% on 8 runs. On 24 runs it was 75%, so 75% is the number I report.

Claude almost never wrote broken logic; it misjudged difficulty. The exact solver caught that.

A Claude agent writes each game in TypeScript inside a confined workspace. Gates it cannot edit lint, compile and verify it: one generic breadth-first-search verifier proves every level solvable and checks difficulty never drops, for any puzzle genre. Failures become a playbook that is kept only if it improves held-out results. A red-team suite checks that prompt injections can't escape.

Berth-RL

Which ship gets the next free berth at a container port: classic dispatch rules vs reinforcement learning vs an optimal schedule.

PPO never significantly beat the simple WSPT rule. But it learned to hold deep berths free for incoming large ships.

Turning that habit into a two-line rule beat PPO in 3 of 4 scenarios (paired Wilcoxon, p < 0.02).

A reproducible study of dynamic berth allocation on an event-driven Gymnasium simulator. A MaskablePPO dispatcher with a HOLD action is compared against FCFS, SPT and WSPT, and against an OR-Tools CP-SAT schedule that knows every arrival in advance. Four scenarios, three distribution shifts and 5 training seeds, compared with paired Wilcoxon tests per instance.

StreamForge

EventFlow: an e-commerce backend where four services talk only through Kafka events, built to survive duplicates, failures and outages.

An order and its event are written in one database transaction, then relayed to Kafka. Nothing is lost if the broker is down, and tests prove it.

Order, payment, notification and analytics services, each in its own consumer group. Reliability comes from a transactional outbox, idempotent consumers, manual offset commits, retries with exponential backoff and a dead-letter queue. Structured logs and Prometheus metrics show what happened, and Kubernetes manifests deploy it.

Peerlink

Group video calls in the browser, with no media server in the middle.

Every participant connects directly to every other over WebRTC (a mesh), so audio and video never pass through the server. The server's only job is signalling: it relays offers, answers and network candidates between browsers over Socket.IO, and announces who joined or left. Rooms get a random ID and an 8-character password that's stored only as a bcrypt hash. Calls include live text chat.

React and Vite, Node.js, Express, Socket.IO, WebRTC with STUN, MongoDB, JWT, served over HTTPS so browsers allow camera access.

Subscription tracker API

Keeps track of your subscriptions and emails you before each one renews.

Creating a subscription starts a durable workflow that sleeps until 7, 5, 2 and 1 days before the renewal date and sends an email at each step. Because the workflow runs on Upstash rather than in the server's memory, reminders survive restarts, and they stop if the subscription is cancelled. Requests pass through bot detection, attack shielding and a token-bucket rate limit. Sign-up runs in a MongoDB transaction with bcrypt-hashed passwords.

Node.js, Express, MongoDB with Mongoose validation, JWT, Upstash Workflow, Arcjet, Nodemailer.

Phishing detection pipeline

Flags phishing websites from 30 signals in their URL and page, as a pipeline that can be retrained end to end.

Trained on 11,055 labelled websites, using signals such as an IP address in the URL, SSL state and URL length. Each stage saves its own artifacts: ingestion from MongoDB, schema checks and a KS-test drift report between train and test data, KNN imputation, then a grid search over five classifiers that keeps the best one. Every run's precision, recall and F1 are tracked in MLflow on DagsHub. A FastAPI service retrains on request and scores an uploaded CSV.

Python, scikit-learn, pandas, MongoDB, MLflow, DagsHub, FastAPI, Docker.

Movie recommender

Describe what you feel like watching in plain words, and get four films back.

Searches 44,584 films released between 1874 and 2020. Each film's title, year, lead actor, director and plot summary are embedded with e5 into a Chroma vector store. A query first retrieves the 10 nearest films, then a cross-encoder reads each query and film pair together and re-ranks them, keeping the best four. Results show posters from TMDB.

Python, LangChain, sentence-transformers (e5-base-v2, MS MARCO cross-encoder), Chroma, Gradio, TMDB API.
